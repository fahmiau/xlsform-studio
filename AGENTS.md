# AGENTS.md

Instructions for AI coding agents working in this repo. Read [CONTEXT.md](./CONTEXT.md) for the project map and current status, [README.md](./README.md) for commands, [plan.md](./plan.md) for architecture decisions (`AD-1`…`AD-15`), and [docs/adr/](./docs/adr/) for recorded spikes and platform workarounds.

## Ground rules

- **Stay lazy:** smallest working diff, no speculative abstractions, no new dependencies without strong justification (check `plan.md` and `docs/adr/` first).
- **Match existing code style:** Prettier + ESLint are the source of truth — run `pnpm lint` and `pnpm format:check` before finishing.
- **Root-cause fixes:** before editing a shared function, grep all callers. Fix once where all callers route through.
- **Test discipline:** non-trivial logic (branch, loop, parser, data path) ships with a test; bug fixes include a regression test. `src/core` has a **≥ 90% line coverage gate** — do not weaken it.
- **No silent suppressions:** no new `@ts-ignore`, `eslint-disable`, `.skip`, or weakened thresholds without a written reason in code/docs and the PR/commit.
- **Privacy & logging:** never write secrets, user file paths, or workbook contents to logs.

## Hard constraints (enforced by ESLint / CI)

- **`src/core/**` purity (`AD-1`):** pure TypeScript over plain data only. No React, no Zustand/zundo, no Tauri, and no imports from `@/state/*`, `@/features/*`, `@/ipc/*`, `@/lib/*`, or `@/components/*`. Dependencies point inward only.
- **One shared XPath tokenizer (`AD-9`):** `src/core/xpath/tokenize.ts` is the single source of truth for XPath lexical structure across CodeMirror highlighting/diagnostics, autocomplete context detection (`src/core/xpath/context.ts`), lint rules (`XLS-004`, `005`, `008`, `011`), and token-aware refactoring. Never introduce parallel regex or Lezer XPath parsers.
- **Pure operations & atomic undo (`AD-2`):** `src/core/ops/*` exports pure `(data, args) => data` functions. Every user-level action (including composite actions like rename + propagate or accepting AI staged changes) maps to **one** `workbookStore.apply(...)` / `set` call → **one** `zundo` history entry (`limit: 100`).
- **Split state stores (`AD-3`):**
  - `workbookStore`: `WorkbookData` only (tracked by `zundo`).
  - `derivedStore`: `variableMap`, `choicesByList`, `groupTree`, `rowIndexById`, `diagnostics` (recomputed from document changes; never in undo history, never exported).
  - `uiStore`: active sheet/cell/selection, `collapsedGroupIds`, language view mode, panel visibility, staged AI diff UI state.
  - `prefsStore`: non-secret user preferences (`tauri-plugin-store`).
  - `stagingStore` (Stage 6): AI Build Mode `{ base, draft, diff }`.
- **Row & cell invariants (`AD-4`, `AD-5`, `AD-14`):**
  - `Row.id` (`RowId`) is an internal `nanoid`, never exported to `.xlsx`.
  - `Row.cells` holds `Record<ColumnKey, string>` only (all cell values are strings). Internal flags go in `Row.meta` (`nameLocked?: boolean` on choices rows, inferred on open per `AD-14` and preserved in recovery snapshots).
  - Column headers are stored **verbatim** as written in the file; semantics and aliases (`list name` → `list_name`, `image` → `media::image`, etc.) come from `resolveColumn` in `src/core/model/columns.ts`.
- **Generated IPC bindings (`AD-7`):** `src/ipc/bindings.ts` is generated by `tauri-specta`. Never hand-edit; regenerate with `pnpm bindings` and verify with `pnpm bindings:check`.
- **Zero WebView network access & secret isolation (`AD-7`, `AD-8`):** CSP has no external `connect-src`. BYOK API keys live only in the OS credential store (`keyring` crate) and never enter the WebView; AI HTTP streaming goes through the Rust `ai_proxy` command.

## Multi-agent stage orchestration (if running the staged plan)

When executing stages via delegated subagents/threads:

- **Pattern per stage:** Implementation → Review → Fix round (if majors/minors require code changes) → Re-review → **Pause for human checkpoint** before the next stage.
- **Provider / Models (per user workflow):** OpenCode Go provider (`deepseek v4.1 flash (max)` for execution/fixes; `glm 5.3 flash (max)` for independent read-only review and re-review).

## Workflow & Definition of Done

1. Check `plan.md`, `CONTEXT.md`, and `plans/stage-N-*.md` to confirm current stage tasks and acceptance criteria. Architecture deltas require an ADR in `docs/adr/` or explicit stage-plan notes.
2. Implement with small, focused commits in Conventional-Commits style (`feat(core): …`, `fix(lint): …`, `chore(ci): …`). Tick completed task checkboxes in `plans/stage-N-*.md`.
3. Run all verification gates before declaring work done:
   - `pnpm lint`
   - `pnpm typecheck`
   - `pnpm test` (and `pnpm coverage` when `src/core` is touched — must stay ≥ 90% lines)
   - `pnpm format:check`
   - `pnpm bench:lint` (when `src/core/lint`, `src/core/xpath`, or `src/core/indexes` is touched — local median target ≤ 15 ms; CI uses `LINT_BENCH_LIMIT_MS=25`)
   - `pnpm test:e2e` (when UI flows change)
   - **If Rust (`src-tauri/**`) is touched:**
     - `cargo fmt --manifest-path src-tauri/Cargo.toml --check`
     - `cargo clippy --manifest-path src-tauri/Cargo.toml -- -D warnings`
     - `cargo test --manifest-path src-tauri/Cargo.toml`
   - **If IPC commands/types are touched:** `pnpm bindings:check`
4. Reference-form tests and benchmarks depend on generated fixtures: run `pnpm fixtures` if `tests/fixtures` is missing or stale.

## Environment & platform gotchas

- **Windows host:** PowerShell is the default shell; `pnpm` scripts work cross-platform.
- **Toolchain pins:** Node ≥ 22 (`.nvmrc`), `pnpm` 12 (`pnpm-workspace.yaml`), Rust stable (`rust-toolchain.toml`).
- **Tauri & Cargo pins (`docs/adr/0002-tauri-dependency-pins.md`):** `tauri = "=2.12.4"`, `tauri-plugin-dialog = "=2.6.0"`, `tauri-plugin-fs = "=2.4.5"`, `tauri-specta = "=2.0.0-rc.25"`, `specta = "=2.0.0-rc.25"` are pinned deliberately. Do not bump without reading ADR 0002.
- **Windows Smart App Control / Application Control (`os error 4551` or transient `E0463`):** fresh Rust build-script or proc-macro binaries may be transiently blocked by Windows policy. **Do not change Rust code to "fix" this.** Wait a few seconds and re-run `cargo test`/`cargo build` once or twice; if a specific crate stays blocked, run `cargo clean -p <crate>` and retry.
- **Third-party fixtures:** `tests/fixtures/xlsx/real-world` contains pyxform fixtures under `BSD-2-Clause` (`third-party/pyxform-LICENSE`). Do not relicense or modify valid corpus fixtures in ways that break the zero-false-positive lint gate (`src/core/lint/corpus.test.ts`).
- **Mocked E2E vs native runtime:** Playwright E2E tests (`tests/e2e/`) run against the Vite dev server with mocked Tauri IPC (`@tauri-apps/api/mocks`) — they do not verify Rust commands or WebView2 accelerator key behavior (`docs/adr/0002-tauri-dependency-pins.md`). Always state in reports what was verified in `pnpm tauri dev` vs Playwright/jsdom.
